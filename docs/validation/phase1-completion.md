# Phase 1 Completion Matrix

This matrix is the authoritative implementation and evidence index for the local Windows Phase 1. The feature catalog remains the one-to-one baseline map; this document groups related rows so evidence is maintainable.

## Scope correction

Phase 1 is the local Windows 11 x64 client. Thirty-five catalog rows that require a control plane, gateway, centralized policy, enterprise assurance, advanced workspace management, or first-enterprise-release evidence were moved to later delivery phases. No baseline row was removed.

- Release build: warnings are errors; latest isolated build has 0 warnings and 0 errors.
- Automated tests: 102 passing across Core, Infrastructure, RDP Host, and Desktop suites (24 Core, 38 Infrastructure, 23 RDP Host, 17 Desktop), including inheritance, two-stage migration and append-only audit enforcement, canonical identity, total DNS/TCP deadlines, exact import semantics/types/encodings/bounds, generated hostile RDG cases, strict bracketed IPv6 rejection, folder integrity/depth, watermark/redaction, ordered session-state work, Windows High Contrast and contrast-safe palettes, accessible summaries, isolated app-data resolution, independent two-tab teardown, pre-connect disconnect state, actionable logon mapping, compatible-control probing, actual COM prompt-only/full-screen/redirection configuration readback, explicit automatic-reconnect continuation, and full-screen monitor-resolution limits.
- Visible Windows inspection: the exact rebuilt framework-dependent Release executable launches the updated responsive shell, retains the existing inventory, exposes meaningful UI Automation names, renders dark and light themes clearly, opens an invalid-host session with a readable environment-labelled tab and an airspace-safe status/full-screen toolbar, restores the original dark preference, drains/closes the session, and exits normally. Earlier inspection also covered the connection editor, help, import rows, and keyboard workflow.
- Visible local workflow: sample import reported one discarded sensitive field, committed one selected connection, detected the repeat import as an unselected duplicate, exercised saved-list shortcuts, opened/closed an invalid-host session with an actionable error, and retained inventory/favorite state after restart.
- Isolated runtime database inspection: both compiled migrations apply to a clean inventory, SQLite integrity is `ok`, audit updates/deletes are rejected by database triggers, and no sensitive schema columns or raw `password` marker exist.
- Runtime persistence inspection: the user-local SQLite database remains intact with two connection profiles and eleven audit events. Automated UI launches use a separate empty validation database rather than modifying the user's inventory.
- Release/package security: the 170-file multi-pattern scan covers quoted assignments, private keys, credentialed URIs, RDP password blobs, and common access-token prefixes; packaging reopens the signed MSIX to verify its exact identity/version/x64 architecture, independently validates Authenticode, rejects PDB and sensitive-name payloads, and writes the final SHA-256 manifest.
- Release-acceptance evidence: `record-phase1-acceptance.ps1` validates a fixed 21-check schema, a Windows 11 x64 client-workstation SKU, and the signed package, then writes a timestamped JSON result with no target, account, credential, machine-name, or free-form-note fields. `test-msix-install.ps1 -ManualAcceptance` keeps the installed package open for the human walkthrough, requires a normal zero-exit close, and then performs package/trust/data cleanup. A completed installed workflow requires that machine-generated manual-window evidence, while clean install/uninstall and WACK pass claims additionally require version-2 JSON/XML whose Windows 11 workstation identity, package hash, and signer satisfy the acceptance contract; the certification XML hash and recognized passing result are rechecked. The recorder fails unless every required environment-backed check passes; touch/pen alone may be not applicable when suitable hardware is unavailable.
- Release-acceptance preflight: the isolated clean-install runner temporarily uses only the local-machine Trusted People store, removes only trust it added, verifies packaged-data cleanup, and rejects Windows Server, Windows 10, non-x64 Windows, the wrong package identity/version/architecture, invalid signatures, existing installations or user data, and non-elevated mutation. Package and Windows App Certification Kit preflights pass for signed x64 package SHA-256 `9850A008A55CEC8FA12C7EEB91FF868EC0C27BC34B153A568132AD1BB4DCF066`; this developer account is correctly reported as non-clean, so elevated clean-user execution remains pending.
